# K3 GUI 首期规格

状态：已确认
日期：2026-08-23

实现状态：本分支已完成 GUI 播放纵向切片、默认麦克风录音与实时监听、在线歌词搜索、右侧歌曲导入分轨、TUI 共享播放及
录音模块迁移、GUI 文案集中化、Slint 组件交互测试、自动性能预算和 Linux 发行内容门禁。第 16 节仍需取得 Ubuntu 24.04
Wayland/X11 CI、真实声卡延迟、歌词同步和 HiDPI 的外部验收结果；进度与证据记录在
`docs/gui-acceptance.md`，不把尚未运行的外部验收误标为通过。

## 1. 目标

K3 新增基于 Slint 的 Linux 桌面前端，同时保留现有 CLI 和 TUI。GUI、TUI 与 CLI
共享工程格式、领域规则和应用命令，但各自采用适合桌面或终端的交互方式。长期目标是
逐步达到功能能力对齐，而不是让 GUI 取代 TUI。

首期交付一个完整的播放纵向切片，用它验证桌面框架、共享应用层、音频线程、工程持久化
和 Linux 发行链路能够稳定协作。

## 2. 首期范围

首期 GUI 必须支持：

1. 无参数启动与桌面化首次设置；
2. 选择并保存单个 `projects_root`；
3. 扫描、排序、搜索和刷新工程；
4. 加载工程但保持暂停；
5. 播放、暂停、重新开始、前后 5 秒跳转；
6. 拖动或点击进度条跳转；
7. 在 Original、Accompaniment 和 Vocals 之间切换；
8. 调节 0% 到 100% 的主音量；
9. 在 -6 到 +6 半音之间调整并重置工程升降调；
10. 展示自动跟随的同步歌词，并允许点击歌词跳转；
11. 在工程或轨道不完整时降级显示；
12. 在音频或工程错误后保持应用可用并提供重试；
13. 记住上次打开的工程，但再次启动时从头、暂停加载；
14. 使用鼠标和键盘完成全部核心操作；
15. 从头播放伴奏并录制默认麦克风，录制期间保留进度跳转、暂停、音轨、Key、音量和实时监听控制；
16. 停止后保存不可变 dry take、写回工程，并让最新 take 可立即试听；
17. 在线搜索同步歌词、预览多个时长匹配候选，确认后原子保存并立即重新加载。
18. 在右侧内容区选择本地音频和分离档位，后台创建工程并分轨；已有工程须明确确认替换 stem，完成后刷新工程库。

## 3. 明确不在首期范围

- 原始音乐目录批量扫描和分轨队列；
- 本地 LRC 导入；
- take 列表管理、删除以及人声效果；
- 手动音频设备选择；
- 专辑封面、艺术家和专辑元数据；
- 全屏演唱模式、第二显示器和自动隐藏控制；
- macOS GUI 发行；
- 软件渲染 fallback；
- 遥测、崩溃上传和自动更新检查。

## 4. Workspace 与模块

```text
k3-core       工程与领域模型、工程持久化
k3-app        UI 无关的应用命令、状态快照和播放模块
k3-audio      GUI 与 CLI 共用的变调音频 source
k3-cli        现有 CLI/TUI
k3-gui        Slint 桌面前端
```

`k3-app` 是深模块。其界面只暴露用户命令、只读状态快照、同步 `PlaybackEngine` 和明确
错误，不暴露 Slint、Ratatui 类型或工程 JSON 的内部表示。GUI 使用后台
`PlaybackService` 的快照订阅；TUI 使用同一个 `PlaybackEngine`。默认麦克风采集、实时
监听和录音时间轴落盘位于 `k3-app`，由 GUI 与 TUI 共同复用。变调算法只在 `k3-audio`
实现一次，由 GUI 与 CLI 共同复用。分轨、在线歌词编排和 take 效果渲染仍保留在
`k3-cli`。

## 5. 播放模块

`PlaybackService` 在独立工作线程中拥有音频 adapter。前端发送以下类型的命令：

- 加载工程；
- 播放或暂停；
- 跳转到绝对位置或相对跳转 5 秒；
- 重新开始；
- 切换轨道；
- 设置音量；
- 设置或重置升降调；
- 重试当前失败操作；
- 停止服务。

前端只订阅不可变状态快照，不主动轮询，也不为每条命令创建等待线程。快照至少包含当前工程和轨道、可用轨道、播放状态、位置、
时长、音量、升降调、歌词时间轴和可恢复错误。音频解码、文件扫描和工程 JSON I/O 不得
在 Slint 事件线程执行。

轨道切换保持时间位置和播放/暂停状态。首期允许出现短暂间隙，切换期间重复操作应被
禁用。默认优先选择 Accompaniment；没有可用伴奏时选择 Original。播放初始保持暂停。

进度条拖动时只更新预览时间，释放后发送一次 seek；点击进度条立即 seek。操作前后的
播放/暂停状态保持不变。

## 6. 工程与设置

TUI、CLI 和 GUI 共享同一份 `project.json`。工程标题、素材路径、歌词、分轨状态、
takes、延迟补偿、升降调和效果均属于工程数据。GUI 改变升降调时必须写回工程。

工程写入采用命令级事务：短暂锁定工程，读取最新文档，只应用本次窄变更，再原子保存。
长时间任务不得在结束时保存一份陈旧的完整工程对象。多个 K3 进程同时访问同一工程时
不得静默丢失更新。

GUI 使用独立、带 schema version 的设置文件，存放于平台标准用户配置目录。首期字段：

- `projects_root`；
- 主音量；
- 窗口尺寸；
- 上次打开的工程 ID。

当前轨道、播放位置和播放/暂停状态不持久化。首次启动只选择 `projects_root`，不要求
`music_root` 或分轨 worker 配置。设置页可更改工程根目录；正在播放时必须先确认，
新目录验证失败时保留旧配置。已有工程根目录时，选择界面必须提供关闭图标，并允许用
`Escape` 取消返回；主界面中的目录图标与当前路径位于同一行且靠右。

## 7. 工程库行为

启动时扫描工程；窗口重新获得焦点时刷新；用户也可手动刷新。首期不使用 filesystem
watcher。刷新后按工程 ID 保持选择。当前工程在磁盘上变化时不自动中断播放，而是显示
可执行 Reload 的提示。

列表按标题稳定排序，并提供大小写不敏感的 Unicode 子串过滤。不实现拼音、模糊搜索、
标签或高级索引。

未分轨或分轨失败的工程仍显示。只要 Original 可用就允许播放；缺失的 Accompaniment
或 Vocals 控件置灰并解释原因。源文件缺失时工程保留在列表中并显示 `Repair needed`。

## 8. 界面与视觉

GUI 的用户可见文字首期全部使用英文。Slint 文案集中在 `ui/strings.slint`，Rust adapter
文案集中在 `ui_text` 模块，为后续语言包保留 seam。中文歌曲名、歌词和文件名保持原样。

主窗口采用：

```text
┌──────────────┬──────────────────────────────────────┐
│ Search       │ Song title · track state             │
│              │                                      │
│ Projects     │          synchronized lyrics         │
│              │       current line / entry mark      │
│              │                                      │
├──────────────┴──────────────────────────────────────┤
│ stem              transport          key · volume   │
└─────────────────────────────────────────────────────┘
```

视觉采用克制的“排练室监听屏”方向：歌词区域使用近黑舞台，当前待唱行使用柔和舞台黄
和一条同色短入句线；已经唱过的行明显退暗，后续歌词保持中性灰白。当前行只通过字号、
亮度和入句线建立层级，不使用卡片或大面积背景；侧栏和控制区继续使用深靛蓝，保持安静、
精确。不得简单复制 TUI，也不得堆叠通用 dashboard 卡片或通用霓虹播放器渐变。

排版分为两个明确角色：Source Han Sans CN 负责歌曲、歌词和界面正文，系统等宽字体负责
时间码、区块标签、调号与数值。底部按真实任务分为 Stem、Transport、Key / Volume，
但不显示重复的分区标题。三个控制组共享一条水平中心线；`−5s`、Record、Play、Monitor、
`+5s`、扬声器图标和音量滑杆也必须位于同一中心线上。录音与监听不在标题区重复显示操作按钮；
录音开始时默认开启监听，用户可在录音期间关闭。界面不依赖装饰动画；键盘焦点和禁用状态必须
保持清晰。

正式界面直接使用 Slint，并建立仅覆盖实际需求的小型 K3 组件集：ActionButton、
PlayButton、TransportIconButton、TrackPill、SectionLabel 和歌词行。颜色、排版、间距、圆角和状态来自统一
design tokens。Refresh、Retry、Reload、Folder、Close、Play / Pause、Restart 和 Volume
等具有通用图形语义的动作使用居中的矢量图标，不显示重复文字或音量百分比，但必须保留
accessible label。按钮默认不显示描边，只通过 hover、键盘焦点和按下状态的背景变化
提供反馈。时间跳转、调号和确认类操作不得为了视觉一致性强行改成纯图标。
播放和暂停状态只由底部的 Play / Pause 图标表达，标题区右上角不重复显示 `Playing` 或
`Paused`；该区域继续保留播放时间，并只在加载或错误等需要用户注意时显示状态文字。

发行包捆绑开放许可的 UI 字体和完整 CJK fallback，并包含字体许可证，避免精简 Linux
系统缺少中文字形。

## 9. 歌词交互

歌词流自动跟随播放位置，当前行位于主视觉区域，前后歌词逐级减弱。点击带时间戳的歌词
立即跳转并恢复自动跟随。用户手动滚动后暂时解除自动跟随，在歌词标题栏显示
`Follow current line` 操作，不得悬浮遮挡歌词。

歌词区不常驻显示“点击歌词可跳转”等教学文案。可发现的直接操作由界面反馈和用户探索
完成，避免提示噪音抢占歌词注意力。

下一句进入最后三秒时，在该行上方显示三个舞台黄提示点，并按秒从右向左逐个熄灭；
相邻歌词不足一秒时不显示，避免快速歌词持续闪烁。倒计时规则由 `k3-app` 共享，TUI
可将同一数值呈现为数字，GUI 只负责点状视觉。

没有同步歌词时显示 `No synced lyrics`，播放功能保持可用。首期不提供任何歌词修改或
联网获取能力。

## 10. 键盘与无障碍

所有核心操作必须同时支持鼠标和键盘。使用 Slint key bindings 建立以下基础映射：

- `Space`：播放或暂停；
- `Left` / `Right`：后退或前进 5 秒；
- `Up` / `Down`：调整音量；
- `1` / `2` / `3`：Original / Accompaniment / Vocals；
- `Escape`：关闭当前最上层弹窗，或取消工程目录选择；
- `Ctrl/Cmd+F`：聚焦搜索；
- `Ctrl/Cmd+R`：刷新工程库。

输入框聚焦时不得触发单键播放命令。所有图标按钮必须有英文 accessible label 和清晰的
焦点样式；不依赖常驻文字说明。指针单击必须在同一次操作中获得焦点并执行动作，不得要求
先点击聚焦、再点击执行。Tab、Enter、Space 和方向键应遵循桌面控件习惯。

## 11. 错误、日志与隐私

音频设备不可用、文件损坏或切轨失败时，应用继续显示工程和歌词。播放栏进入明确的
disabled/error 状态，展示简短错误与 Retry。不得用连续模态弹窗阻断操作。

详细诊断写入标准用户 state 目录下的滚动日志；顶层 About 界面显示日志位置。日志记录平台、
Slint/音频错误和应用状态转换。GUI 默认不联网，不上传任何数据。

Slint 无法初始化 GPU 或显示后端时，`k3-gui` 输出英文诊断、日志路径和使用 `k3 tui`
的回退说明，并返回非零状态。首期不承诺软件渲染或自动打开终端。

## 12. 框架 spike、决策与依赖策略

正式实现前必须通过代表性 spike。验证矩阵：

- 当前 Arch Linux Wayland；
- Ubuntu 24.04 Wayland；
- Ubuntu 24.04 X11。

Spike 必须验证窗口启动、Unicode/CJK、HiDPI 与缩放、1000 项虚拟列表、后台状态更新、
`PlaybackService` 的播放/暂停/seek、release binary 和 Linux 打包。

GUI 框架使用经过验证的 crates.io 精确版本并提交 `Cargo.lock`，不得使用 `*`、宽松版本
或跟踪 git main。升级必须作为独立维护任务并重新运行完整 GUI 验证。

若任一核心门槛无法通过，应停止正式 GUI 实现，保存失败环境、最小复现和门槛结果，
再用同一 spike 评估其他框架。不得为了挽救选型把框架类型泄漏进 `k3-app`。

2026-08-23 在当前 Arch Linux Wayland 机器（Intel HD 3000，OpenGL ES 3.0，无 Vulkan）
执行了相同的硬件渲染启动门禁：

- GPUI 0.2.2：失败，Blade 返回 `NoSupportedDeviceFound`；
- Iced 0.14.0：失败，wgpu 默认和强制 GL 均返回 `GraphicsAdapterNotFound`；
- Slint 1.17.1：通过，femtovg/OpenGL ES 在 Wayland 和强制 X11 下均成功启动窗口。

因此正式实现固定使用 Slint 1.17.1 的 `backend-winit` 与 `renderer-femtovg`，不启用软件
renderer。Ubuntu 24.04 Wayland/X11 仍是发布前硬门槛，不能由当前 Arch 结果替代。
PR `verify` job 在 Ubuntu 24.04 上分别使用 Xvfb 和 Weston headless 执行 X11/Wayland
启动门禁；最新分支的实际运行结果记录在 `docs/gui-acceptance.md`。

Slint 按 Royalty-free Desktop, Mobile, and Web Applications License 2.0 使用；应用必须在
顶层可访问的 About 界面展示官方 `AboutSlint` 组件，以满足归属条件。

## 13. 性能预算

在验证机器上：

- 启动后 2 秒内窗口可交互；
- 1000 个工程的首屏在 1 秒内出现，其余内容可后台补齐；
- 普通输入在下一帧得到视觉反馈；
- 本地文件点击 Play 后 300 ms 内开始播放；
- 歌词显示与播放位置的误差不超过 100 ms；
- UI 主线程不得执行可感知的目录扫描、工程读取或音频解码。

自动测试直接约束 1000 工程扫描和首帧预算，并约束 UI 命令提交不阻塞调用线程。真实声卡
起播延迟、歌词听感同步和 HiDPI 仍按 `docs/gui-acceptance.md` 进行平台验收。

## 14. 测试

测试通过公开 interface 验证行为：

1. `k3-app` 使用临时工程库和 fake 音频 adapter 测试工程发现、用户命令、状态转换、
   歌词窗口和错误恢复；
2. 播放模块通过可替换 adapter 测试线程命令、快照和失败时序；
3. Slint 组件测试验证首次点击、callbacks、全局快捷键、输入焦点隔离、禁用状态、Escape
   弹层顺序、主要呈现状态和 1000 工程首帧；
4. CI 不依赖真实声卡；真实听音、Wayland/X11、HiDPI 和 GPU 初始化进入平台验收；
5. `cargo fmt --check`、严格 Clippy 和 workspace 全量测试必须通过。

## 15. Linux 发行

现有 Linux 发行包同时包含 `k3` 和 `k3-gui`。Windows 与 macOS 包首期不包含 GUI。
包内增加：

- `k3-gui`；
- 应用图标；
- `.desktop` 文件；
- UI/CJK 字体及许可证；
- 中文安装与故障排查说明。

不提供需要 root 权限的自动安装器。用户可按文档手动安装 `.desktop` 文件和图标。
发行 workflow 使用 `scripts/verify-linux-gui-package.sh` 拒绝缺少 GUI、桌面入口、图标或
许可证的 Linux 包。

## 16. 完成标准

只有以下条件全部满足，首期才算完成：

- 选定框架 spike 通过三种 Linux 显示环境；
- `k3-app` 与 `k3-gui` seam 落地；
- TUI 的播放切片复用 `k3-app` 且现有行为未回归；
- 本规格第 2 节的用户流程全部可用；
- 多进程工程写入不静默丢失更新；
- 自动化测试和性能预算通过；
- 本地日志、字体、Linux 打包和桌面文件完成；
- 项目文档完成更新；
- workspace 格式化、Clippy 和测试全部通过。

## 17. 后续路线

GUI 后续按以下顺序扩展：

1. 歌曲导入与分轨队列，同时重新引入 `music_root`；
2. 本地歌词导入与在线歌词搜索；
3. take 管理和效果。
